
**Robocopy** -ს ალტერნატივები **Macbook** - ზე:
**Mac** - ზე მუშაობისას, ფაილების კოპირების ეს სამი ბრძანება ერთი შეხედვით ერთსა და იმავეს აკეთებს, თუმცა "კაპოტის ქვეშ" სრულიად განსხვავებული ფილოსოფია და შესაძლებლობები აქვთ.

```bash
1.                                              - - - `/` დირექტორიის შეგთავსები
   
2. rsync -auvP Source/ Destination/             - - - ( -u ეს ყველაზე ნაღდია) ძველ ტექსტის შიგთავსაც ცვლის ახლით (% პროგრეს) 

3. rsync -avP Source/ Destination/              - - -   აკოფირებს, ამატებს ახალს.( -P % პროგრესს ანახებს)  
4. rsync -auvP Source/ Destination/ --dry-run   - - - ( --dry-run ) წინასწარ ნახო რა მოხდება
5. rsync -auvP --delete Source/ Destination/     - - -   ახალს ამატებს, ძველს შლის.!!!
   
6. rsync -avz --progress Source/ Destination/  
7. rsync -ah --progress Source/ Destination/    - - - მგონი ამის გადმოწერის სიჩქარე უფრო ნელია ვირდე მაგალითად  -avz-თი
   
8. ditto -V Source/ Destination/                              - - -   ჩვეულებრივი კოპირება
9. ditto -c -k --sequesterRsrc /path/to/folder archive.zip    - - - ფაილის დაარქივება
10. ditto Source/ Destination/.                                - - - რამდენიმე საქაღალდის გაერთიანება (Merge)
   
11. cp -Rpv Source/ Destination/                         - - - ჩვეულებრივი კოპირება 
12. ( --progress რომ დაამატო ამაზე არ მუშაობს )
```

## 1.  rsync ( Remote Sync )

**rsync:** ეს არის მძლავრი და ფართოდ გავრცელებული ბრძანების სტრიქონის (command line) უტილიტა Unix-ის მსგავს სისტემებში, მათ შორის macOS-ში. ის საუკეთესოა ფაილებისა და კატალოგების ეფექტური სინქრონიზაციისთვის, რადგან ტრაფიკის მინიმიზაციის მიზნით აკოპირებს ფაილების მხოლოდ შეცვლილ ნაწილებს.

- **მთავარი მახასიათებელი:** სინქრონიზაცია. თუ ***კოპირება გაწყდა***, `rsync` ***გააგრძელებს იქიდან, სადაც გაჩერდა.***
    
- **გამოყენების შემთხვევა:** დიდი მოცულობის მონაცემების ბექაპი, სერვერებთან მუშაობა.
- **მოქნილობა:** მუშაობს როგორც ლოკალურად, ისე დისტანციურ სერვერებზე **SSH**-ის საშუალებით.
- **ძირითადი ბრძანება:**

```bash
rsync -avP /path/to/local/folder/ username@server_ip:/path/to/destination/
```

**დეტალური განმარტება:**   

| ფლეგი | ფუნქცია                            | როდის გამოვიყენოთ?                     |
| ----- | ---------------------------------- | -------------------------------------- |
| -a    | არქივირება (უფლებების შენარჩუნება) | ყოველთვის.                             |
| -v    | პროცესის ჩვენება                   | როცა გინდათ ხედავდეთ, რა ხდება.        |
| -z    | კომპრესია                          | ნელი ქსელის ან ტექსტური ფაილების დროს. |
| -P    | პროგრესი და გაგრძელება **%**       | დიდი ფაილების გადაწერისას.             |
.

- `-a` : ( archive ) : - - - ეს არის ყველაზე მნიშვნელოვანი ფლეგი. იგი ინარჩუნებს ფაილების **უფლებებს (permissions), თარიღებს და სიმბოლურ ბმულებს.** ასევე, ის ავტომატურად ნიშნავს **რეკურსიულ** კოპირებას (ქვესაქაღალდეების ჩათვლით).  
- `-v` : ( verbose ) : - - - გაჩვენებთ პროცესს დეტალურად — **რომელი ფაილი კოპირდება მოცემულ მომენტში.**  
- `-P` : ( partial/progress ) : - - - გაჩვენებთ პროგრესს ( **რამდენი % გადაიწერა** ) და წყვეტის შემთხვევაში გაძლევთ საშუალებას კოპირება იქიდან გააგრძელოთ, სადაც გაჩერდა.  
- `--progress` : Показывает процесс копирования файлов 
- ***არავითარი*** `--delete` : - - - რადგან თქვენ გინდათ, რომ სერვერზე არსებული ფაილები **არ წაიშალოს**, ბრძანებაში არ ჩაწეროთ `--delete` ფლეგი. `rsync` ნაგულისხმევად არაფერს შლის დანიშნულების ადგილზე.  
	- თუ **destination** ადგილზე ***წაშლა გვინდა ყველაფრის***, რაც **Source** -ში არაა, მაშინ ვწერთ: `--delete` 
- `-z`: ( compress ): მონაცემების შეკუმშვა გადაცემისას (კარგია ქსელში მუშაობისას).

.

> [!NOTE] **მნიშვნელოვანი ნიუანსი საქაღალდის ბოლოში** `/` **ნიშანთან დაკავშირებით:**  
> `rsync`- ისთვის დიდი მნიშვნელობა აქვს, დაწერთ თუ არა დახრილ ხაზს (`/`) წყარო საქაღალდის ***ბოლოში***:  
> 1. **/path/to/folder/ (ხაზით) :** თუ ***ბოლოს*** დაუწერთ  ხაზს (`/`) , ის ***დააკოპირებს შიგთავსს*** . თუ არა — თავად საქაღალდეს. 
> 2. **/path/to/folder (ხაზის გარეშე) :** სერვერზე შეიქმნება ***თავად საქაღალდე*** `folder` და მასში ჩაიყრება ყველაფერი.

.
#### რას აკეთებს `-z` ( Compression ) ? 


> [!NOTE] **შეჯამება**
> 1. სახლის პირობებში, უკეთესი და ჩქარი იქნება - - - (`-avP`) 
> 2. გარეთ, ინტერნეტით დაკავშირებული - - - (`-avzP`)


ბრძანება `rsync -avz` გადაცემისას აკომპრესირებს (კუმშავს) მონაცემებს. ეს ნიშნავს, რომ ინფორმაცია ინტერნეტში/ქსელში უფრო მცირე მოცულობით მოძრაობს, ხოლო დანიშნულების ადგილზე (თქვენს zimaOS-ზე) ისევ იშლება.  
**როდის არის** `-z` **უკეთესი?**  

- **ნელი ინტერნეტი/ქსელი:** თუ ფაილებს გადასცემთ გარე სერვერზე ინტერნეტით ან სუსტი Wi-Fi კავშირით.  
    
- **ტექსტური ფაილები:** დოკუმენტები, კოდი (`.txt`, `.html`, `.json`, `.sql`) ძალიან კარგად იკუმშება და გადაცემა საგრძნობლად ჩქარდება.  
    

**როდის არ არის რეკომენდებული?**  

- **სწრაფი ლოკალური ქსელი (Gigabit LAN):** თუ თქვენი მაკი და zimaOS ერთი და იმავე როუტერზე არიან შეერთებული კაბელით, დამატებითმა კომპრესიამ შესაძლოა **შეანელოს** პროცესი. რატომ? იმიტომ, რომ მაკის პროცესორს სჭირდება დრო დასაკუმშად, ხოლო სერვერს — გასაშლელად. ხშირად ქსელი უფრო სწრაფია, ვიდრე ეს "შეკუმშვა-გაშლის" პროცესი.  
    
- **უკვე შეკუმშული ფაილები:** თუ გადაგაქვთ ვიდეოები (`.mp4`, `.mkv`), სურათები (`.jpg`, `.png`) ან არქივები (`.zip`, `.gz`), მათი ხელახლა შეკუმშვა `-z` ფლეგით აზრს მოკლებულია — ისინი ფაქტობრივად აღარ პატარავდება, მაგრამ პროცესორის რესურსი მაინც იხარჯება.

**შეჯამება**: 
თუ სახლის სწრაფ ქსელში ხართ და დიდ ვიდეოებს ან ფოტოებს ყრით, ჩემი პირველი ვერსია (`-avP`) უფრო სწრაფი იქნება. თუ სადმე სხვაგან ხართ და ინტერნეტით უკავშირდებით სერვერს, მაშინ თქვენი ვერსია (`-avzP`) ნამდვილად აჯობებს.


#### მაგალითი რეალურ ცხოვრებაში ( შეცდომის არიდება )

ვთქვათ, გინდათ წინასწარ ნახო რა მოხდება ბრძანების შესრულებისას (შეცდომის ასარიდებლად) : 

 ბრძანებას ბოლოში დაუმატეთ `--dry-run`. ეს სიმულაციას გააკეთებს — გაჩვენებთ რას იზამდა ბრძანება, მაგრამ რეალურად არაფერს გადაწერს. თუ სია სწორი იქნება, მერე მოაშორეთ `--dry-run` და გაუშვით რეალურად.

```bash
rsync -auvP Source/ Destination/ --dry-run
```

.

#### `-u` (update) ფლეგი

`rsync` -ის დროს, წყაროს (**Source**) ფაილში არსებული "ტექსტური" ფაილი მიაჩნია ჭეშმარიტად და Destination ფაილში შიგთავს(ტექსტს) არ ცვლის თუ სპეციალურად არ მივუთითეთ. ის უბრალოდ გადააწერს (**Overwrite**) მას, მიუხედავად იმისა, რომ სერვერზე(**Destination**) არსებული ფაილი შესაძლოა უფრო ახალი ან უფრო დიდი იყოს.

იმისათვის, რომ მომავალში ასეთი "**დანაკლისი**" აიცილოთ თავიდან და დაიცვათ სერვერზე არსებული უფრო ახალი ფაილები, უნდა გამოიყენოთ `-u` ფლეგი. 

```bash
rsync -auvP /path/to/source/ user@server:/path/to/dest/
```

რას შეცვლის ეს?  

- **-u (update):** ეს ფლეგი ეუბნება `rsync`-ს: "თუ დანიშნულების ადგილზე ფაილი უკვე არსებობს და მისი შეცვლის თარიღი უფრო ახალია, ვიდრე წყაროში არსებულის, **არ შეეხო მას** და გამოტოვე".  
    
- ამ შემთხვევაში, თქვენი სერვერის ფაილი (რომელშიც მეტი ტექსტი ეწერა და უფრო გვიან დარედაქტირდა) ხელუხლებელი დარჩებოდა.


#### `-b` (backup)

თუ მაინც გინდათ ფაილის გადაწერა, მაგრამ გეშინიათ სერვერზე არსებული ვერსიის დაკარგვის, გამოიყენეთ ბექაპის ფუნქცია:
```bash
rsync -avzP --backup --suffix=_old /source/ /dest/
```

ეს ბრძანება სერვერზე არსებულ ფაილს კი არ წაშლის, არამედ სახელს შეუცვლის (მაგალითად: `file.txt_old`) და ახალ ვერსიას გვერდით მიუწერს.

## 2.  ditto ( macOS Specific )

ეს არის Apple-ის მიერ შექმნილი ბრძანება, რომელიც სპეციალურად **macOS**-ის ფაილურ სისტემებზეა ოპტიმიზირებული.

- **მთავარი მახასიათებელი:** ის საუკეთესოდ ინარჩუნებს **Resource Forks**-ს და **macOS**-ის სპეციფიკურ მეტამონაცემებს (**Metadata**), რასაც ხშირად `cp` ან `rsync`-ი კარგავენ.
    
- **გამოყენების შემთხვევა:** აპლიკაციების (`.app`) კოპირება ან სისტემური ფაილების გადატანა, სადაც მეტამონაცემების შენარჩუნება კრიტიკულია.
    
- **ძირითადი გასაღებები:**
    
    - `-V`: დეტალური პროცესი.
        
    - `-c`: ქმნის **PKG** ან **ZIP** არქივს კოპირების ნაცვლად.
        
    - `-x`: არქივის ამოარქივება.
        
- **მაგალითი:** `ditto /წყარო /დანიშნულება`


> [!NOTE] მნიშვნელოვანი განსხვავებებე ***rsync & ditto***
> 1. `rsync` უფრო მეტად ***ქსელურ სინქრონიზაციასა*** და ეფექტურობაზეა ორიენტირებული,
> 2. `ditto` სპეციალურად Apple-ის ***ფაილური სისტემისთვისაა*** შექმნილი


თუ მას **Robocopy**-ს ადარებ, საუბარია **Apple-ის ჩაშენებულ `ditto` ბრძანებაზე**, რომელიც macOS-ის ტერმინალში (Terminal) გამოიყენება. ის ძალიან ძლიერი ინსტრუმენტია და ბევრი პარამეტრით მართლაც ჰგავს Windows-ის Robocopy-ს.

აი, როგორ მუშაობს ის:

### რატომ არის `ditto` უკეთესი, ვიდრე ჩვეულებრივი `cp` (copy)?

- **ინარჩუნებს ატრიბუტებს:** ის აკოპირებს არა მხოლოდ ფაილს, არამედ მის ყველა მეტამონაცემს, უფლებებს (Permissions) და "Resource Forks"-ს, რაც Mac-ის ფაილური სისტემისთვის კრიტიკულია.
    
- **სტრუქტურის შენარჩუნება:** ის ზუსტად იმეორებს საქაღალდეების იერარქიას.
    
- **დაარქივება:** მას შეუძლია პირდაპირ შექმნას ან ამოარქივოს PKG და ZIP ფაილები.
    

#### 1. საქაღალდის სრული კოპირება (Robocopy-ს მსგავსად)

თუ გინდა, რომ **საქაღალდე A**-ს შიგთავსი გადაიტანო **საქაღალდე B**-ში  ყველა უფლების შენარჩუნებით და ასევე მანამდე B-ში რაც იყო ისიც შენარჩუნებულია. `ditto` არ შლის დანიშნულების ადგილას არსებულ ფაილებს, :

```shell
ditto -V /path/to/source /path/to/destination
```

- `-V` (Verbose) — გაჩვენებს თითოეული ფაილის კოპირების პროცესს (როგორც Robocopy-ს პროგრესი).
    

#### 2. ფოლდერის დაარქივება ZIP-ში

ეს ბრძანება ბევრად უფრო საიმედოა Mac-ზე, ვიდრე სტანდარტული `zip`:

```shell
ditto -c -k --sequesterRsrc /path/to/folder archive.zip
```

- `-c` — შექმენი არქივი (Create).
    
- `-k` — გამოიყენე PKZip ფორმატი.
    
- `--sequesterRsrc` — ინახავს Mac-ის სპეციფიკურ ფაილებს (metadata) ისე, რომ სხვა სისტემებზე (Windows) არ გამოიწვიოს შეცდომები.
    

#### 3. რამდენიმე საქაღალდის გაერთიანება (Merge)

განსხვავებით `cp`-სგან, `ditto` არ შლის დანიშნულების ადგილას არსებულ ფაილებს, ის "აშრევებს" (Merge) ახალ ფაილებს ძველებზე:

Bash

```shell
ditto /source/folder /destination/folder
```

## rsync vs ditto: ძირითადი განსხვავებები

|**მახასიათებელი**|**rsync**|**ditto**|
|---|---|---|
|**მთავარი დანიშნულება**|ფაილების სინქრონიზაცია და რეზერვირება|ფაილების ზუსტი ასლის შექმნა (Cloning)|
|**Apple-ის სპეციფიკა**|ზოგადი Unix ხელსაწყო|სპეციალურად macOS-ისთვის შექმნილი|
|**მეტამონაცემები**|ინახავს სტანდარტულ ატრიბუტებს|ინახავს ყველაფერს (Resource Forks, ACLs)|
|**ქსელში მუშაობა**|იდეალურია (SSH მხარდაჭერით)|ძირითადად ლოკალური კოპირებისთვის|
|**სისწრაფე**|სწრაფია განმეორებითი კოპირებისას|სწრაფია პირველადი სრული კოპირებისას|

### როგორ ვმართოთ ისინი (სასარგებლო რჩევები):

1. **სუფთა ასლისთვის:** გამოიყენეთ `ditto`, თუ გსურთ სისტემური საქაღალდეების ან აპლიკაციების გადატანა, რადგან ის არაფერს გამოტოვებს.
    
2. **ყოველდღიური "ბექაფისთვის":** გამოიყენეთ `rsync -avz`, რადგან ის მხოლოდ შეცვლილ ფაილებს გადაწერს და დროს დაზოგავს.
    
3. **დაარქივებისთვის:** `ditto -c -k --sequesterRsrc` შექმნის PKZip არქივს, რომელიც Mac-ის ყველა მეტამონაცემს შეინახავს.



## 3. cp ( copy )

macOS-ზე (ისევე როგორც სხვა Unix-სისტემებში) `cp` არის ფუნდამენტური ბრძანება ფაილების დასაკოპირებლად. თუმცა, macOS-ის ფაილურ სისტემას (APFS) აქვს თავისი თავისებურებები, რაც `cp`-ს მუშაობას სპეციფიკურს ხდის.


ეს არის Unix-ის კლასიკური ბრძანება. ის ყველაზე მარტივი და სწრაფია, როცა გჭირდებათ ***ერთი ფაილის ან საქაღალდის სწრაფი გადატანა , და B საქაღალდეში რამე სხვას არ ეხება - - - ( ჩვეულებრივი კოპირება )***.

- **მთავარი მახასიათებელი:** არ გააჩნია "ინტელექტი". ის უბრალოდ აკოპირებს ყველაფერს თავიდან.
- **გამოყენების შემთხვევა:** ლოკალური, მცირე ზომის ფაილების სწრაფი კოპირება.
- **სინტაქსი:** `cp [options] source_file destination_file`
- **ძირითადი გასაღებები:**
    
    - `-R` ან `-r`  (Recursive): გამოიყენება საქაღალდეების (folders) დასაკოპირებლად. ამის გარეშე საქაღალდეს ვერ დააკოპირებთ.
    - `-p` (Preserve) : ინარჩუნებს ფაილის ატრიბუტებს (შექმნის თარიღი, უფლებები).
    - `-v`: (Verbose) გაჩვენებთ პროცესს.
    - **`cp -X` (No Extended Attributes):** მაკისთვის სპეციფიკური ფლაგია. ის აკოპირებს ფაილს "სუფთად", macOS-ის დამატებითი მეტამონაცემების გარეშე (მაგალითად, ფერადი თეგების ან Finder-ის ინფორმაციის გარეშე).
        
- **მაგალითი:** `cp -Rp /წყარო /დანიშნულება`


```bash
cp -Rpv ~/Documents/my_folder ~/Desktop/backup_folder
```


### მნიშვნელოვანი: 
თუ ბოლოს დაუწერთ დახრილ ხაზს (`/`), ის დააკოპირებს შიგთავსს. თუ არა — თავად საქაღალდეს.

### გრაფიკული აპლიკაციები 

**გრაფიკული აპლიკაციები:** თუ თქვენ უპირატესობას გრაფიკულ ინტერფეისს ანიჭებთ, არსებობს აპლიკაციები, რომლებიც Robocopy-ს ანალოგიურ ფუნქციონალს გვთავაზობენ:

- **Carbon Copy Cloner:** პოპულარული კომერციული აპლიკაცია Mac-ზე რეზერვირებისა (backup) და დისკების კლონირებისთვის.
- **ChronoSync:** კიდევ ერთი მძლავრი გადაწყვეტილება ფაილების სინქრონიზაციისა და რეზერვირებისთვის.
- **TeraCopy:** უტილიტა, რომელიც შექმნილია ფაილების უფრო სწრაფი და საიმედო კოპირებისთვის, შეცდომების აღდგენის ფუნქციით.

### რომელი აირჩიოთ?

თუ გაინტერესებთ რეკომენდაცია კონკრეტული ამოცანისთვის:

1. **სრული სისტემური ასლისთვის:** საუკეთესოა **Carbon Copy Cloner**, რადგან მას შეუძლია შექმნას ჩამტვირთავი (bootable) დისკის ასლი.
    
2. **რთული სინქრონიზაციისთვის:** **ChronoSync** გამორჩეულია იმით, რომ გაძლევთ საშუალებას ძალიან დეტალურად გაწეროთ წესები, თუ რომელი ფაილი საინით გადაადგილდეს.
    
3. **მარტივი და სწრაფი კოპირებისთვის:** **TeraCopy** საუკეთესოა მაშინ, როცა უბრალოდ ბევრი დიდი ფაილის გადატანა გსურთ და გინდათ დარწმუნდეთ, რომ პროცესი არ შეწყდება რომელიმე ფაილზე წარმოქმნილი შეცდომის გამო.
    


## script

იმისათვის, რომ ფაილები დანიშნულების ადგილას (**B**) მხოლოდ დაემატოს და არსებული მონაცემები არ წაიშალოს (incremental update), თითოეულ ბრძანებას თავისი მიდგომა აქვს.

აი, სამივე ვარიანტის სკრიპტი. შეცვალეთ `SOURCE_PATH` და `DEST_PATH` თქვენი რეალური მისამართებით.

---

### 1. `rsync` სკრიპტი ( ყველაზე ჭკვიანი ვარიანტი )

`rsync` საუკეთესოა ამ საქმისთვის, რადგან ის ავტომატურად ადარებს ფაილებს და მხოლოდ სიახლეებს გადაწერს.


```bash
#!/bin/bash
SOURCE="/Users/სახელი/Documents/A/"
DEST="/Users/სახელი/Documents/B/"

# -a: არქივის რეჟიმი (ინარჩუნებს ყველაფერს)
# -v: აჩვენებს პროცესს
# -u: (Update) გამოტოვებს ფაილებს, რომლებიც დანიშნულების ადგილას უკვე არის და უფრო ახალია
rsync -avu "$SOURCE" "$DEST"

echo "rsync დასრულდა!"
```

### 2. `ditto` სკრიპტი (macOS-ის "მშობლიური" გზა)

`ditto` თავისი ბუნებით არ შლის ფაილებს დანიშნულების ადგილას, ის უბრალოდ "აშენებს" (merging) ახალ მონაცემებს ძველზე.


```bash
#!/bin/bash
SOURCE="/Users/სახელი/Documents/A"
DEST="/Users/სახელი/Documents/B"

# ditto ავტომატურად აერთიანებს (Merge) საქაღალდეებს
# -V: გვაჩვენებს თითოეულ კოპირებულ ფაილს
ditto -V "$SOURCE" "$DEST"

echo "ditto დასრულდა!"
```

### 3. `cp` სკრიპტი (კლასიკური მეთოდი)

რადგან `cp` არ არის სინქრონიზაციის ხელსაწყო, ჩვენ უნდა გამოვიყენოთ სპეციალური გასაღები `-n`, რომ უკვე არსებული ფაილები არ გადაეწეროს (Overwrite).

```bash
#!/bin/bash
SOURCE="/Users/სახელი/Documents/A/."
DEST="/Users/სახელი/Documents/B"

# -R: რეკურსიული (საქაღალდეებისთვის)
# -p: ატრიბუტების შენარჩუნება
# -n: (No clobber) არ გადააწეროს ზემოდან უკვე არსებულ ფაილებს
cp -Rpn "$SOURCE" "$DEST"

echo "cp დასრულდა!"
```

### მნიშვნელოვანი განსხვავებები ამ სკრიპტებში:

|**ბრძანება**|**ქცევა "B" საქაღალდეში**|
|---|---|
|**rsync -u**|აკოპირებს მხოლოდ ახალ ან შეცვლილ ფაილებს.|
|**ditto**|აკოპირებს ყველაფერს და "აზავებს" (Merge) არსებულთან. საუკეთესოა მეტამონაცემებისთვის.|
|**cp -n**|აკოპირებს ყველაფერს, მაგრამ თუ ფაილი უკვე არსებობს "B"-ში, მას საერთოდ არ ეხება (არც აახლებს).|

### როგორ გაუშვათ ეს სკრიპტები:

1. გახსენით **TextEdit** და ჩაწერეთ კოდი.
    
2. შეინახეთ ფაილი `.sh` გაფართოებით (მაგ: `backup.sh`).
    
3. ტერმინალში მიეცით გაშვების უფლება: `chmod +x backup.sh`.
    
4. გაუშვით ბრძანებით: `./backup.sh`.
