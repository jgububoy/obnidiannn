# Wayland vs X11(Xorg)

## რა არის Wayland და X11
**Wayland** და **X11** (X Window System) არის ორი მთავარი **გრაფიკული სერვერი** (Display Server / Protocol) Linux და Unix-ის მსგავს ოპერაციულ სისტემებში. ისინი მართავენ ურთიერთობას ოპერაციულ სისტემას, გრაფიკულ დრაივერს და აპლიკაციებს შორის — კერძოდ, პასუხისმგებლები არიან ფანჯრების გამოჩენაზე, მაუსის კურსორის გადაადგილებაზე, კლავიატურის ღილაკებზე და ეკრანზე გამოსახულების დახატვაზე.

### 1. რა არის X11 (X Window System)?

* **რა არის:** ვეტერანი არქიტექტურა, რომელიც ათეულობით წელია (1980-იანებიდან) Linux-ის სტანდარტს წარმოადგენს.
* **როგორ მუშაობს:** მუშაობს "კლიენტ-სერვერის" პრინციპით. თავად X სერვერი აკონტროლებს ეკრანს, ხოლო თითოეული აპლიკაცია (Firefox, ტერმინალი და ა.შ.) არის კლიენტი, რომელიც სერვერს სთხოვს ფანჯრის დახატვას. X11 აპლიკაციებს უფლებას აძლევს პირდაპირ მიმართონ ეკრანს და ერთმანეთის მონაცემებსაც კი უყუროან (რაც ძველ სისტემებში უსაფრთხოების ნაკლოვანება იყო).
* **რისთვის გვჭირდება:** ძველი, მყარი სტანდარტია, რომელსაც ყველა ძველი პროგრამა და დისტრიბუტივი იდეალურად უჭერს მხარს.

### 2. რა არის Wayland?

* **რა არის:** თანამედროვე პროტოკოლი, რომელიც შეიქმნა X11-ის მოსაძველებელი და რთული არქიტექტურის შესაცვლელად.
* **როგორ მუშაობს:** Wayland-ში თავად შემქმნელი (Compositor — მაგალითად, GNOME-ის Mutter ან KDE-ს KWin) ასრულებს სერვერის როლსაც. აპლიკაცია თავად ხატავს თავის ფანჯარს ბუფერში და უგზავნის კომპოზიტორს, რომელიც მათ ერთიან სურათად აწყობს და ეკრანზე გამოჰყავს. შუამავლები და ზედმეტი ნაბიჯები გამოტოვებულია.
* **რისთვის გვჭირდება:** იმისათვის, რომ მივიღოთ თანამედროვე გრაფიკა, მაღალი წარმადობა, ასობით ჰერციანი მონიტორების (High Refresh Rate) უპრობლემო მხარდაჭერა, გლუვი ანიმაციები და გაუმჯობესებული უსაფრთხოება (აპლიკაციები ვერ "უსმენენ" ერთმანეთის კლავიატურის დაკლიკებებს).

### მთავარი განსხვავებები Wayland-სა და X11-ს შორის

| მახასიათებელი | X11 (Xorg) | Wayland |
| --- | --- | --- |
| **არქიტექტურა** | მოძველებული, მონოლითური კლიენტ-სერვერული მოდელი. | თანამედროვე, مستقیمული (Direct rendering) კომპოზიტორზე დამყარებული. |
| **სიჩქარე და ლატენტობა** | მეტი შუალედური ნაბიჯი, რამაც შეიძლება გამოიწვიოს მიკრო-შეყოვნება. | ფანჯრები თავად ხატავენ და პირდაპირ გზავნიან ეკრანზე — მუშაობს უფრო სწრაფად და გლუვად. |
| **უსაფრთხოება** | სუსტი: ნებისმიერ აპლიკაციას შეუძლია წაიკითხოს სხვა აპლიკაციის მონაცემები (მაგ. კლავიატურის ლოგირება). | ძლიერი (Isolation): აპლიკაციები მკაცრად იზოლირებულია ერთმანეთისგან. |
| **ეკრანის გაზიარება / ჩაწერა** | რთული, საჭიროებდა დამატებით ჰაკებს და მოდულებს. | ინტეგრირებული და სტანდარტიზებული (მაგ. PipeWire-ის გამოყენებით). |
| **თავსებადობა** | **იდეალური:** ძველი პროგრამები, დისტრიბუციები და ხელსაწყოები (როგორიცაა ზემოხსენებული `xkill`) უპრობლემოდ მუშაობს. | **კარგი, მაგრამ ზოგჯერ მოითხოვს ხიდებს:** ძველმა პროგრამებმა შეიძლება XWayland ფენის გამოყენება მოითხოვონ. |

## Wayland-სა და X11-ს შორის გადართვა

Wayland-სა და X11-ს შორის გადართვა ძირითადად ხდება **გრაფიკული შესვლის ეკრანიდან (*Login Screen / Display Manager*)**, სანამ სისტემაში შეხვალ. პროცესი დამოკიდებულია იმ გრაფიკულ გარემოზე (Desktop Environment), რომელსაც იყენებ (მაგ. Ubuntu-ზე ძირითადად GNOME-ია, სხვა დისტრიბუციებზე KDE Plasma და ა.შ.).

### 1. შესვლის ეკრანიდან (Login Screen / GDM / SDDM)

1. **გამოდი სისტემიდან (Log Out)** ან გადატვირთე კომპიუტერი, რომ მოხვდე შესვლის ფანჯარაში.
2. მიუახლოვდი იმ ადგილს, სადაც შენს სახელს ირჩევ, მაგრამ **ჯერ პაროლი არ ჩაწერ**.
3. მოძებნე **პატარა კბილანის (Settings / Gear)** ხატული, ან სამი წერტილი, ან მენიუ (ჩვეულებრივ ეკრანის ქვედა მარჯვენა კუთხეშია ან სახელსა და პაროლს შორის).
4. დააკლიკე და სიიდან აირჩიე სასურველი რეჟიმი:
	* **GNOME** (ან შესაბამისი გარემო) — იმუშავებს **Wayland**-ზე.
	* **GNOME on Xorg** (ან X11) — იმუშავებს ძველ **X11** პროტოკოლზე.
5. შეიყვანე პაროლი და შეավე სისტემაში — ის უკვე არჩეულ პროტოკოლს გამოიყენებს.

---

### 2. კონფიგურაციის ფაილიდან (თუ დისპლეი მენეჯერი არ გაძლევს არჩევნის საშუალებას)

თუ იყენებ **GNOME**-ს და **GDM** (GNOME Display Manager) მენეჯერს, შეგიძლია ხელით მიუთითო სისტემას:

1. გახსენი კონფიგურაციის ფაილი ტერმინალში:
```bash
sudo nano /etc/gdm3/custom.conf

```

2. იპოვე ხაზი `#WaylandEnable=false` (თუ კომენტარშია).
3. **X11-ზე გადასასვლელად:** მოხსენი `#` და მიუშვი მნიშვნელობა `false`:
```text
WaylandEnable=false

```


*(თუ ისევ Wayland გინდა, მიუთითე `true` ან უბრალოდ დააკომენტარე ხაზი).*
4. შეინახე ფაილი (`Ctrl+O`, შემდეგ `Enter`) და გამოხვედი (`Ctrl+X`).
5. გადატვირთე GDM სერვისი ან მთელი სისტემა:
```bash
sudo systemctl restart gdm3

```


## XWayland
**XWayland** არის სპეციალური თავსებადობის ფენა (Compatibility Layer), რომელიც მუშაობს Wayland პროტოკოლზე აგებულ Linux სისტემებზე და საშუალებას აძლევს ძველ, მხოლოდ **X11**-ისთვის შექმნილ პროგრამებს, უპრობლემოდ გაეშვან და იმუშაონ.

როდესაც დისტრიბუტივი გადადის თანამედროვე Wayland სერვერზე, ძველი აპლიკაციები (რომლებიც არ იცნობენ Wayland-ს) პირდაპირ ეკრანზე ვეღარ ხატავენ. XWayland ამ პრობლემას შემდეგნაირად აგვარებს:

### როგორ მუშაობს და რისთვის გვჭირდება?

1. **ხიდის როლი:** ის ქმნის ვირტუალურ X11 გარემოს Wayland-ის შიგნით. ძველი პროგრამა ფიქრობს, რომ ჩვეულებრივ X11 სერვერზე მუშაობს, ხოლო XWayland ამ მონაცემებს ღებულობს და ათავსებს Wayland-ის კომპოზიტორში.
2. **თავსებადობის შენარჩუნება:** ბევრი პოპულარული და ძველი პროგრამა (ან თამაშები, დეველოპერული ინსტრუმენტები) ჯერ კიდევ ეყრდნობა X11-ს. XWayland-ის გარეშე ისინი უბრალოდ ვერ გაეშვებოდნენ Wayland-ის გარემოში.
3. **იზოლაცია:** მიუხედავად იმისა, რომ XWayland ძველ არქიტექტურას იყენებს, ის უზრუნველყოფს, რომ ძველმა აპლიკაციებმა მთლიანად არ დაარღვიონ Wayland-ის უსაფრთხოების სტანდარტები (თუმცა სრულ აბსოლუტურ იზოლაციას ძველი პროტოკოლის გამო ვერ უზრუნველყოფს).

მოკლედ რომ ვთქვათ, XWayland არის **გარდამავალი ხიდი**, რომელიც საშუალებას გვაძლევს გამოვიყენოთ თანამედროვე და სწრაფი Wayland სერვერი ისე, რომ ძველი პროგრამების გაშვებაზე უარის თქმა არ მოგვიწიოს.
