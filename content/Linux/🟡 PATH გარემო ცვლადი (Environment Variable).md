# PATH გარემო ცვლადი (Environment Variable)
 
ოპერაციულ სისტემებში (Windows, macOS, Linux) არსებობს ***სისტემური ცვლადი***, რომელსაც ჰქვია ***PATH***. მასში ჩაწერილია იმ დირექტორიების სიები, სადაც კომპიუტერი ეძებს გამშვებ პროგრამებს (`.exe` ფაილებს), როდესაც ბრძანებას კონსოლიდან (**Terminal / Command Prompt**) სრული გზის გარეშე, მხოლოდ სახელით უშვებ.

ოპერაციულ სისტემებში (Windows, macOS, Linux) არსებობს ***სისტემური ცვლადი***, რომელსაც ჰქვია ***PATH***.
`PATH` არ არის ერთი კონკრეტული დირექტორია - - - ეს არის **დირექტორიების სია (გამოყოფილი ორწერტილებით `:`დირექტორია)**, ***რომელშიც ოპერაციული სისტემა თანმიმდევრულად ეძებს შესასრულებელ/გასაშვებ ფაილებს,*** როდესაც ბრძანებას კონსოლიდან (**Terminal / Command Prompt**) სრული გზის გარეშე, მხოლოდ სახელით უშვებ.

შენს მიერ გაშვებული პროგრამა ან სკრიპტი **უნდა მდებარეობდეს ამ სიის ერთ-ერთ დირექტორიაში**, რომ სისტემამ ის ავტომატურად იპოვოს.

**ძირითადი სისტემური დირექტორიები, რომლებიც სტანდარტულად შედის `PATH`-ში:**

* `/usr/local/bin` — მომხმარებლის მიერ ხელით დაინსტალირებული ან მესამე მხარის პროგრამები.
* `/usr/bin` — პაკეტების მენეჯერით (APT, DNF და ა.შ.) დაინსტალირებული პროგრამების უმეტესობა.
* `/bin` — სისტემისთვის კრიტიკული ძირითადი ბრძანებები (მაგ: `ls`, `cp`, `cat`).
* `/usr/sbin` და `/sbin` — ადმინისტრაციული ბრძანებები, რომლებიც ძირითადად `root` მომხმარებლისთვისაა განკუთვნილი (მაგ: `fdisk`, `iptables`).

**მომხმარებლის პირადი დირექტორიები (ხშირად უმატებენ PATH-ს):**

* `~/.local/bin` ან `~/bin` - - -  მიმდინარე მომხმარებლის მიერ შექმნილი ან გადმოწერილი ინდივიდუალური შესასრულებელი ფაილები.

**საკუთარი სისტემის PATH სიის ნახვა:**

```bash
echo $PATH

```

---

ტერმინალში ნიშანი **`$`** ნიშნავს **ცვლადის მნიშვნელობის გამოთხოვას (ამოკითხვას)**.

როდესაც წერ `$PATH`, ლინუქსს ეუბნები: 
***„მომეცი არა სიტყვა PATH-ის ტექსტი, არამედ იმ ცვლადის შიგთავსი (მნიშვნელობა), რომელიც ამ სახელის უკან იმალება“***.

ასევე, `$`-ს აქვს მეორე მნიშვნელობაც:

* **ტერმინალის დასაწყისში (`$` ნიშანი სტრიქონის ბოლოს):** როდესაც ტერმინალს ხსნი და ხედავ მაგალითად `user@pc:~$`, ეს უბრალოდ ნიშნავს, რომ სისტემა მზადაა და ელოდება შენს ბრძანებას (ნიშნავს ჩვეულებრივ მომხმარებელს, განსხვავებით `root`-ისგან, სადაც `#` წერია).
* **ბრძანების შიგნით (`$PATH`, `$USER`, `$HOME`):** აი აქ კი ის მუშაობს როგორც ცვლადის „ამოძრავების“ ან მიმართვის სიმბოლო.

**მარტივი მაგალითი:**

* თუ დაწერ `echo PATH` (დოლარის გარეშე), ეკრანზე უბრალოდ დაიწერება სიტყვა `PATH`.
* თუ დაწერ `echo $PATH` (დოლარით), სისტემა შიგთავსს ამოიღებს და დაგიწერს რეალურ დირექტორიათა სიას (`/usr/local/bin:/usr/bin:...`).
* 
## PATH ხელით გაწერა: 

ეს არის სრულიად სტანდარტული და მოხერხებული მიდგომა :  

> შეგიძლია ნებისმიერ დამატებით მიერთებულ დისკზე შექმნა საქაღალდე, ჩაყარო შენი სკრიპტები, მიამატო `PATH`-ს და ტერმინალის ნებისმიერი წერტილიდან მხოლოდ სახელით გაუშვა.

პროცესის სრულად დასაყენებლად და გასამართად მიჰყევი ამ თანმიმდევრობას:

#### 1. შესრულების უფლებების მინიჭება: ***chmod***.

დარწმუნდი, რომ დამატებით დისკზე არსებულ სკრიპტ ფაილებს მინიჭებული აქვთ ***execute*** უფლება:
**მაგალითად**: 
```bash
chmod +x /mnt/your_drive/scripts/*
```

ვარსკვლავი (`*`) ნიშნავს - - -  რომ ეს ბრძანება გავრცელდება მითითებულ დირექტორიაში (`/mnt/your_drive/scripts/`) არსებულ ყველა ფაილზე და თითოეულ მათგანს ერთდროულად მიენიჭება გაშვების (**execute**) უფლება.

#### 2. PATH-გარემოში მუდმივი დამატება: ***Shell Config***.

დაამატე შენი დირექტორია კონფიგურაციის ფაილში (მაგალითად, ბაშისთვის `~/.bashrc` ან ზშისთვის `~/.zshrc`):

```bash
echo 'export PATH="$PATH:/mnt/your_drive/scripts"' >> ~/.bashrc
```

- ***ანუ რას ნიშნავს ზედა ბრძანება:*** 

`~/.bashrc` (ან `~/.zshrc`) **არ არის** თავად **PATH**. ეგენი არის უბრალო **ტექსტური ფაილები-ინსტრუქციები** (კონფიგურაციის ფაილები. , რომლებიც ინახება შენს პირად საქაღალდეში.`~` ნიშნავს მთავარ ეგ სახლს, ანუ შენს home დირექტორიას).  ), სადაც ვწერთ წესებს.

თითოეული ამ ფაილის შიგნით კი არის სტრიქონი, რომელიც ამბობს: 
***„აიღე ძველი PATH, მიუმატე ბოლოში ეს ახალი მისამართი და გახადე ეს ახალი სია ჩვენს PATH-ად“***.

ანუ სქემა ასე გამოიყურება:

1. `~/.bashrc` ან `~/.zshrc` არის კონფიგურაციის ფაილი, რომელიც **ტერმინალის გახსნისას იკითხება**.
2. ამ ფაილში ვწერთ ბრძანებას `export PATH="..."`.
3. ზუსტად ეს `export` ბრძანება ქმნის და აახლებს რეალურ სისტემურ `PATH` ცვლადს ოპერატიულ მეხსიერებაში.

მარტივად რომ ვთქვათ: 
ფაილი არის რვეული, სადაც ინახება ჩანაწერი, ხოლო თავად `PATH` არის ის საბოლოო სია, რასაც ტერმინალი ყოველდღიურად იყენებს.

#### 3. ცვლილებების ძალაში შესვლა: ***source***.

გაააქტიურე ცვლილებები მიმდინარე სესიაში:

```bash
source ~/.bashrc
```

ამის ბრძამების  გარეშეც გააქტიურდება, მაგრამ **მხოლოდ იმ ახალ ტერმინალებში, რომლებსაც მომავალში გახსნი**.

* როდესაც ხსნი **ახალ** ტერმინალის ფანჯრებს, ის ავტომატურად კითხულობს `~/.bashrc` ფაილს თავიდან ბოლომდე, ხედავს შენს ახალ დამატებულ მისამართს და მუშაობას იწყებს უკვე განახლებული `PATH`-ით.
* მაგრამ **უკვე გახსნილ, მიმდინარე ტერმინალში** ცვლილებები ავტომატურად არ აისახება, რადგან მან ეს ფაილი მხოლოდ ერთხელ, გაღების მომენტში წაიკითხა და ახლა ძველ მონაცემებს იყენებს მეხსიერებიდან.

სწორედ ამიტომაა საჭირო `source ~/.bashrc` — რომ მიმდინარე, უკვე გახსნილ ტერმინალს ხელახლა გადავათვლევინოთ ფაილი და დროის დაკარგვის (ან ტერმინალის თავიდან ჩართვის) გარეშე მყისიერად გავააქტიუროთ ახალი მისამართი.

#### ვერიფიკაცია:

გადაამოწმე, რომ ახალი გზა წარმატებით დაემატა სისტემურ ცვლადს:

```bash
echo $PATH
```

თუ გამოჩნდა `/mnt/your_drive/scripts`, პრინციპი წარმატებით მუშაობს და ნებისმიერი სკრიპტის სახელი პირდაპირ გაეშვება.
