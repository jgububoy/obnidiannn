# Linux პაკეტების ფორმატი

[Обучение Linux. Лучшие программы для Linux на каждый день - YouTube](https://www.youtube.com/watch?v=e1q1dUuyGFA) 
## 🚀 დომინანტი ფორმატები (Distro-Specific)
[📌 პაკეტების მენეჯერი (1)](📌%20პაკეტების%20მენეჯერი%20(1).md) 
ეს ფორმატები ლინუქსის მსხვილი ოჯახების საფუძველს წარმოადგენს.

| **ფორმატი**                                 | დისტრიბუციები (მაგ.)             | მენეჯერი          | აღწერა                                                                                                                                                |
| :------------------------------------------ | :------------------------------- | :---------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------- |
| ***.DEB***                                  | Debian, Ubuntu, Mint             | **APT, DPKG**     | დებიანის ოჯახის სტანდარტული ფორმატი. ყველაზე ფართოდ გავრცელებული დისტრიბუციების ბაზა.                                                                 |
| ***.RPM***                                  | RHEL, Fedora, CentOS, openSUSE   | **DNF, YUM, RPM** | Red Hat-ის ოჯახის სტანდარტული ფორმატი. ძლიერია კორპორატიულ გარემოში.                                                                                  |
| ***.pkg.tar.zst*** <br>ან ***.pkg.tar.xz*** | Arch Linux, Manjaro, EndeavourOS | **Pacman**        | ფორმატი, რომელიც ცნობილია სიჩქარით და სიმარტივით. პოპულარულია მოწინავე მომხმარებლებში.                                                                |
| ***Ebuild***                                | Gentoo, Funtoo                   | **Portage**       | განსხვავებული მიდგომა: ეს არ არის ბინარული პაკეტი, არამედ სკრიპტი, რომელიც წყარო კოდიდან (Source Code) აკომპილირებს პროგრამას მომხმარებლის სისტემაზე. |
|                                             | MacOS                            | **brew**          |                                                                                                                                                       |

* **`.deb`** - - -  Debian, Ubuntu, Linux Mint და მათი შთამომავალი დისტრიბუტივების პაკეტის გაფართოება.
* **`.rpm`** - - -  Fedora, Red Hat (RHEL), openSUSE და მსგავსი სისტემების პაკეტის **ფორმატი**.
* 
* **`.pkg.tar.zst`** (ან ძველ ვერსიებში `.pkg.tar.xz`) — **Arch Linux**-ის სამყაროში გამოყენებული შეკუმშული პაკეტის არქივი.
ასევე: 

***PKGBUILD***  - - -  არის **Arch Linux**-ის დისტრიბუტივის **სკრიპტი-ფაილი** (ტექსტური ფაილი), რომელიც აღწერს, თუ როგორ უნდა გადმოიწეროს, შეიქმნას და დაინსტალირდეს კონკრეტული პროგრამა პაკეტის მენეჯერის (`pacman` / `makepkg`) გამოყენებით.

***Pacman***  - - -  არის **Arch Linux**-ის და მის ბაზაზე შექმნილი დისტრიბუტივების ძირითადი და ოფიციალური პაკეტების მენეჯერი.  მთავარი ფუნქციაა პროგრამების ინსტალაცია, განახლება, წაშლა და ზოგადად სისტემის მართვა. სახელი მომდინარეობს ფრაზიდან **Package Manager.**
მუშაობს ოფიციალურ საცავებთან (**Repositories**) და Arch User Repository(**AUR**)-სთან.
იყენებს შეკუმშულ პაკეტებს .**pkg.tar.zst** ფორმატით.  ძალიან სწრაფი, მარტივი და ეფექტურია.

---
***dpkg* (Debian Package Manager):** - - - არის **დაბალი დონის** ინსტრუმენტი. ის პირდაპირ მუშაობს უკვე გადმოწერილ `.deb` ფაილებთან — აყენებს, შლის ან ამოწმებს მათ. მისი მთავარი მინუსი ის არის, რომ **არ ამოწმებს და არქაჩებს დამოკიდებულებებს (dependencies)**. თუ პროგრამას სხვა პაკეტები სჭირდება, `dpkg` შეცდომით გაჩერდება, სანამ მათ ხელით არ დააყენებთ.
**დაინსტალირება:** 
```bash
sudo dpkg -i file.deb
```

***apt* (Advanced Package Tool):**  - - - არის **მაღალი დონის** ინსტრუმენტი, რომელიც `dpkg`-ის თავზე მუშაობს. ის აკონტროლებს ონლაინ საცავებს (repositories), ავტომატურად ეძებს, ქაჩავს და აყენებს პროგრამის ყველა საჭირო დამოკიდებულებას. როდესაც ტერმინალში წერთ `sudo apt install` ბრძანებას, ფონზე ისევ `dpkg` აყენებს პაკეტს, მაგრამ მთელ მოსამზადებელ სამუშაოს `apt` აკეთებს.

**ძირითადი განსხვავებების ცხრილი:**

|**მახასიათებელი**|**dpkg**|**apt**|
|---|---|---|
|**დონე**|დაბალი დონის ინსტრუმენტი|მაღალი დონის ინსტრუმენტი|
|**დამოკიდებულებები**|არ მართავს (საჭიროებს ხელით მიბმას)|მართავს ავტომატურად|
|**წყარო**|მუშაობს ლოკალურ ფაილებზე (`.deb`)|მუშაობს ონლაინ საცავებიდან|
|**მთავარი დანიშნულება**|პაკეტის პირდაპირი ინსტალაცია/მოხსნა|ძებნა, განახლება და ინსტალაცია|

## 🌐 უნივერსალური ფორმატები (Universal/Sandboxed)

ეს ფორმატები ***ნებისმიერ დისტრიბუციაზე მუშაობს*** და **იზოლირებულად (sandboxed) აყენებს აპლიკაციებს**.

| **ფორმატი**    | **დისტრიბუციები**           | **მენეჯერი** | **აღწერა**                                                                                                                |
| -------------- | --------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| ***Flatpak***  | ნებისმიერი                  | `flatpak`    | პოპულარულია დესკტოპ მომხმარებლებში. იყენებს **Flathub** საცავს. უზრუნველყოფს კარგ იზოლაციას (Sandbox).                    |
| ***Snap***     | ნებისმიერი (განსაკ. Ubuntu) | `snap`       | Canonical-ის (Ubuntu-ს შემქმნელი) ფორმატი. იყენებს **Snap Store**-ს. მარტივი განახლება.                                   |
| ***AppImage*** | ნებისმიერი                  | არ საჭიროებს | **პორტაბელური** ფორმატი, რომელიც არ საჭიროებს ინსტალაციას. ერთ ფაილში მოთავსებულია პროგრამა და ყველა მისი დამოკიდებულება. |

#### AppImage

* ***.AppImage*** - - -  **პორტატული** აპლიკაციის ფაილი (მსგავსია Windows-ის პორტატული `.exe`-ს, **არ საჭიროებს დაყენებას**, უბრალოდ ეძლევა გაშვების უფლება). როგორც Windows-ის პორტატული აპლიკაციები.  დამოუკიდებელი ფაილი, რომელსაც ინახავ კომპიუტერში სადმე , აძლევ გაშვების უფლებას და რთავ ინსტალაციის გარეშე.
	* **როგორ მუშაობს:** მასში უკვე ჩატეულია პროგრამა თავისი ყველა საჭირო ბიბლიოთეკითურთ. არ აინსტალირებს არაფერს სისტემურ საქაღალდეებში, არ ტოვებს "კვალს" რეესტრში (რადგან რეესტრი ლინუქსში არცაა) და არ აბინძურებს სისტემას.
	* **გაშვების პრინციპი:** გადმოწერ ფაილს, მისცემ გაშვების უფლებას (`chmod +x` ან მაუსით მარჯვენა კლიკით _Properties -> Allow executing file as program_), ორჯერ დააწკაპუნებ და მუშაობს. როცა აღარ გჭირდება, უბრალოდ შლი ერთადერთ `.AppImage` ფაილს და კომპიუტერში მისი კვალიც აღარ რჩება.
	* ერთი და იგივე `.AppImage` ფაილი უპრობლემოდ ეშვება როგორც Ubuntu-ზე და Linux Mint-ზე, ისე Fedora-ზე, Arch Linux-ზე ან ნებისმიერ სხვა თანამედროვე ლინუქს დისტრიბუტივზე.
	* **შიდა სტრუქტურა და ISO ანალოგია:** AppImage რეალურად ერთიანი კონტეინერია, რომელიც შიგნით ატარებს როგორც თვითონ პროგრამის ფაილებს, ისე ყველა საჭირო დამოკიდებულებას. მისი გახსნა (ამოღება) სპეციალური პარამეტრის გამოყენებითაც არის შესაძლებელი, რის გამოც მის სტრუქტურას ხშირად ISO образ-საც ადარებენ.

#### Flatpak და Snap

-  ***.flatpak*** / ***.snap*** - - - არის **უნივერსალური აპლიკაციების ფორმატი**, რომელიც ცენტრალიზებულად, ნებისმიერ დისტრიბუტივზე აყენებს პროგრამას თავისივე იზოლირებული ბიბლიოთეკებით.
* **მცდარი წარმოდგენა:** ისინი არ წარმოადგენენ პატარა გამშვებ ფაილებს (როგორც Windows-ის ვებ-ინსტალატორები). თქვენ არ იწერთ ცალკეულ "გამშვებ ფაილს" — იყენებთ კლიენტს (ბრძანებას ან გრაფიკულ მაღაზიას), რომელიც ცენტრალური საცავიდან (***Flathub*** ან ***Snap Store***) ქაჩავს და აყენებს მთლიან, უკვე აწყობილ პაკეტს თავისი საჭირო ბიბლიოთეკებითურთ. სწორედ ამიტომ, ისინი ფაილის ზომით პატარები **არ არიან** — პირიქით, რადგან ყველაფერი შიგნით აქვთ, ხშირად საკმაოდ დიდ ადგილს იკავებენ დისკზე.
* **ინტეგრაცია:** ისინი რეალურად ინსტალირდებიან სისტემაში (სპეციალურ იზოლირებულ დირექტორიებში); სისტემა თავად აინტეგრირებს მათ აპლიკაციების მენიუში, მართავს და აფდეითებს.


***Snap* პაკეტები (.snap)**

* **მთავარი უპირატესობა:** ტექნიკური იდეა მდგომარეობს უნივერსალურობაში. რადგან პაკეტს შიგნით მოყვება ყველა საჭირო ბიბლიოთეკა, ის ერთნაირად უნდა გაეშვას ნებისმიერ დისტრიბუტივზე.
* **მოწყვლადი მხარეები:** მთავარი პრობლემა იზოლაციის მექანიზმია. „Sandbox“ გარემოს გამო სისტემურ რესურსებს ხშირად ნელა უერთდება, რამაც ადრე აპლიკაციების გახსნის სიჩქარეზე და ინტერფეისზე იქონია გავლენა.
* **მართვის პრინციპი:** მთელ პროცესს ფონურ რეჟიმში აკონტროლებს სპეციალური დემონი — `snapd`. (დებიანის ოჯახისათვის დაყენება: `sudo apt install snapd`)
* **snap პაკეტების დაყენება:** `sudo snap install <პაკეტის_სახელი>`


***Flatpak* პაკეტები (.flatpak)**

* **რას წარმოადგენს:** კონცეპტუალურად ჰგავს Snap-ს და დოკერის პრინციპით იზოლირებულ კონტეინერში ეშვება.
* **მომზადება და საიდან ვიწერთ:** საჭიროებს ინსტრუმენტის და პლაგინის დაყენებას  `sudo apt install flatpak` .  ხოლო გრაფიკული ინტეგრაციისთვის ხშირად ამატებენ `gnome-software-plugin-flatpak`-ს ან შესაბამის დისტრიბუტივის მაღაზიის პლაგინს. ძირითადი კატალოგია **flathub.org**, სადაც პროგრამები იყრის თავს.
* **ძირითადი ბრძანებები:**
* ფაილის გაფართოება: `.flatpakref`
* ინსტალაცია: `flatpak install <ფაილის_სახელი>`
* განახლება: `flatpak update`
* დაყენებული პროგრამების სია: - - -  `flatpak list`


## ⚙️ სხვა მნიშვნელოვანი მეთოდები/ფორმატები

ეს მეთოდები პაკეტების მართვის სისტემის წინამორბედებია ან გამოიყენება სპეციალური შემთხვევებისთვის.

| **#**   | **მეთოდი**                            | **ტიპი** | **აღწერა**                                                                                                                              |
| ------- | ------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
