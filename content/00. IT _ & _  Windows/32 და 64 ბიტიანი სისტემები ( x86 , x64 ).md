# 32(x86) და 64(x64) ბიტიანი სისტემები ( არქიტექტურა )

კომპიუტერულ სამყაროში „***ბიტიანობა***“ და „***არქიტექტურა***“ ფუნდამენტური ცნებებია, რომლებიც განსაზღვრავენ, თუ როგორ „აზროვნებს“ და მუშაობს პროცესორი.

### რა არის პროცესორის არქიტექტურა?

***პროცესორის არქიტექტურა***  - არის წესების, ინსტრუქციებისა და ტექნიკური გადაწყვეტილებების ერთობლიობა, რომელიც განსაზღვრავს, თუ როგორ ურთიერთქმედებს პროგრამული უზრუნველყოფა ( **Software** ) აპარატურასთან ( **Hardware** ).

წარმოიდგინე, რომ პროცესორი არის მშენებელი. არქიტექტურა არის მისი „ინსტრუმენტების ნაკრები“ და „ენების ცოდნა“. ის განსაზღვრავს, რა ზომის ტვირთის აწევა შეუძლია მას ერთჯერადად და რა ბრძანებებს ესმის.

### 32 - ბიტიანი vs 64 - ბიტიანი: რა განსხვავებაა?

ეს ციფრები მიუთითებს იმაზე, თუ რა მოცულობის ინფორმაციის დამუშავება შეუძლია **პროცესორს ერთ ციკლში** (ერთ „დარტყმაზე“) და რამდენი მეხსიერების (RAM) მისამართვა შეუძლია მას.

> მთავარი განსხვავება **RAM** -ების მაქსიმალური რაოდენობა

| მახასიათებელი                   | 32-ბიტიანი (x86)                | 64-ბიტიანი (x64)                           |
| ------------------------------- | ------------------------------- | ------------------------------------------ |
| **ოპერატიული მეხსიერება (RAM)** | ***მაქსიმუმ 4 GB***             | თეორიულად **16 ექსაბაიტი** (მილიონობით GB) |
| **ინფორმაციის დამუშავება**      | პატარა „ულუფებით“               | ბევრად დიდი „ულუფებით“                     |
| **გამოთვლის სისწრაფე**          | ნელი რთულ ამოცანებში            | ძალიან სწრაფი (ვიდეო, 3D, თამაშები)        |
| **თავსებადობა**                 | ვერ უშვებს 64-ბიტიან პროგრამებს | უშვებს როგორც 64, ისე 32-ბიტიანებს         |

**რატომ არის 4 GB ლიმიტი 32-ბიტზე?**  
მათემატიკურად,  $2^{32}$   არის დაახლოებით 4.2 მილიარდი. ეს არის მაქსიმალური რაოდენობა იმ „უჯრების“ (მისამართების), რომელთა დანახვაც შეუძლია **32-ბიტიან** სისტემას RAM-ში. 

**64-ბიტიანის** შემთხვევაში ეს ციფრი ( $2^{64}$ ) ასტრონომიულია, რაც თანამედროვე კომპიუტერებს საშუალებას აძლევს გამოიყენონ 8, 16, 32 ან მეტი გიგაბაიტი მეხსიერება.

### რატომ 32, 64 და არა x100?

ეს ყველაფერი დაკავშირებულია **ორობით (Binary) სისტემასთან**, რომელზეც მუშაობს კომპიუტერი. კომპიუტერისთვის არსებობს მხოლოდ ორი მდგომარეობა: **0** (დენი არ გადის) და **1** (დენი გადის).

1. **ორჯერადობა:** ყველა გამოთვლა ეფუძნება 2-ის ხარისხებს.
    
    - $2^5 = 32$
        
    - $2^6 = 64$
        
    - $2^7 = 128$
        
2. **რატომ არა 100?** რიცხვი 100 არ არის 2-ის ხარისხი. კომპიუტერული ტრანზისტორებისთვის ბევრად ეფექტური და ლოგიკურია მუშაობა სისტემაში, რომელიც სრულად ემთხვევა ორობით ლოგიკას. 100-ბიტიანი სისტემის შექმნა გამოიწვევდა უზარმაზარ დანაკარგებს გამოთვლებში და არასაჭირო სირთულეს აპარატურულ დონეზე.
    
3. **სტანდარტიზაცია:** ინდუსტრია მიჰყვება ამ გზას (8 -> 16 -> 32 -> 64), რათა პროგრამული კოდი იყოს პროგნოზირებადი. შემდეგი ეტაპი, სავარაუდოდ, იქნება **128 ბიტი**, თუმცა დღევანდელი საჭიროებებისთვის 64 ბიტიც კი იმაზე მეტ რესურსს გვთავაზობს, ვიდრე უახლოეს მომავალში დაგვჭირდება.

მოკლედ რომ ვთქვათ: **32 და 64** არის მათემატიკური „კანონზომიერება“ ორობით სამყაროში, ხოლო **არქიტექტურა** არის გეგმა, თუ როგორ გამოიყენოს პროცესორმა ეს მათემატიკა საქმისთვის.

ხომ არ გაინტერესებს, შენს კონკრეტულ მოწყობილობაზე როგორ შეამოწმო არქიტექტურა?


### ბიტიანობა  :

**ბიტიანობა აქვს როგორც პროცესორს (Hardware), ისე ოპერაციულ სისტემას (Software).**

აქ მოქმედებს „იერარქიის“ პრინციპი: **ოპერაციული სისტემა ვერ იქნება იმაზე „მაღალი“ ბიტიანობის, ვიდრე პროცესორია.**

აი, როგორ მუშაობს ეს ლოგიკა:

#### 1. პროცესორი (Hardware) განსაზღვრავს მაქსიმუმს

პროცესორის ბიტიანობა ნიშნავს მის ფიზიკურ შესაძლებლობას — რამდენი მონაცემის გატარება შეუძლია მის შიდა „მაგისტრალებს“.

- თუ შენ გაქვს **64-ბიტიანი პროცესორი**, მას შეუძლია იმუშაოს 64-ბიტიან რეჟიმშიც, 32-ბიტიანშიც და 16-ბიტიანშიც (უკუ-თავსებადობა).
    
- თუ შენ გაქვს ძველი, **32-ბიტიანი პროცესორი**, მას ფიზიკურად არ აქვს იმხელა „მილები“, რომ 64-ბიტიანი ინფორმაციის ნაკადი გაატაროს. მასზე 64-ბიტიან Windows-ს ვერ ჩაწერ.
    

#### 2. ოპერაციული სისტემა (Windows, Linux)

ოპერაციული სისტემა არის „მენეჯერი“, რომელიც ეუბნება პროცესორს, როგორ იმუშაოს.

- შენ შეგიძლია 64-ბიტიან პროცესორზე დააყენო 32-ბიტიანი Windows. ამ დროს პროცესორი იმუშავებს თავისი შესაძლებლობების მხოლოდ ნახევარზე (ვერ დაინახავს 4 GB-ზე მეტ RAM-ს და ვერ გამოიყენებს სწრაფ ინსტრუქციებს).
    
- მაგრამ 32-ბიტიან პროცესორზე 64-ბიტიან სისტემას ვერ დააყენებ — ინსტალაციისას ამოგიგდებს შეცდომას: "Your CPU is not compatible".
    

#### 3. რატომ შეგვიძლია სხვადასხვას ჩაწერა?

ეს შესაძლებელია მხოლოდ იმიტომ, რომ თანამედროვე პროცესორები (x86-64 არქიტექტურა) შექმნილია **უკუ-თავსებადობის** პრინციპით. ინჟინრებმა იცოდნენ, რომ როცა 64-ბიტიანი პროცესორები გამოვიდოდა, ხალხს ჯერ კიდევ ექნებოდა ძველი, 32-ბიტიანი პროგრამები. ამიტომ მათ პროცესორში ჩადეს „თავსებადობის რეჟიმი“.

---

#### შეჯამება: როგორაა დალაგებული „შრეები“?

1. **პროცესორი (საძირკველი):** განსაზღვრავს ლიმიტს (მაგ. 64 ბიტი).
2. **ოპერაციული სისტემა:** ირჩევს, როგორ გამოიყენოს ეს საძირკველი (მაგ. დააყენებ 32-ბიტიან სისტემას).
3. **პროგრამები:** მუშაობენ სისტემის ფარგლებში (64-ბიტიან Windows-ზე შეგიძლია გაუშვა 32-ბიტიანი Google Chrome, მაგრამ პირიქით — არა).
