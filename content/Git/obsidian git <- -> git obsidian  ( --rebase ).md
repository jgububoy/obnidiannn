# obsidian git - - git obsidian

## როცა მხოლოდ ჩემთვის ვიყენებ და ძირითადად ერთ შტოზე: 

[--rebase](--rebase.md)

* `git pull --rebase` - - - - **სწრაფი სინქრონიზაცია (მუშაობის დაწყებამდე):**
* `git add .` -> `git commit -m "შენიშვნა"` -> `git push`  - - - **ცვლილებების გაგზავნა (მუშაობის დასრულებისას):**
* **კონფლიქტის მოგვარება (თუ გამოგრჩა):**
`git pull --rebase` ავტომატურად მიამაგრებს შენს ახალ კომიტებს სერვერზე არსებულის თავზე. თუ ერთსა და იმავე ფაილს მივაწექი ორივე ადგილიდან, git მიგითითებს პრობლემურ ფაილზე. 
შეასწორებ, გააკეთებ `git add`-ს და დაასრულებ `git rebase --continue`-ით.

### **მთავარი წესები და რეკომენდაციები ერთი შტოთი მუშაობისთვის**

* **ყოველთვის დაიწყე `pull`-ით:** როცა ჯდები მეორე კომპიუტერთან, პირველი რაც უნდა გააკეთო, არის საწყისი სინქრონიზაცია. სანამ რამეს დაწერდი, თქვი: `git pull --rebase`. ეს მოქაჩავს იმას, რაც სხვა კომპიუტერიდან გაგზავნე და შენს მიერ დაწერილ კოდს ზემოდან მიაყოლებს.
* **გამოიყენე `--rebase` დროის დაზოგვისთვის:** ჩვეულებრივი `git pull` ქმნის დამატებით „Merge commit“-ებს, რაც ერთ შტოზე მუშაობისას ისტორიას აჭრელებს. `--rebase` ალაგებს შენს კომიტებს სუფთა, სწორ ხაზად.
* **არ დაგრჩეს „ჰაერში“ დაუფიქსირებელი ფაილები:** მუშაობის დასრულებისას ყოველთვის დარწმუნდი, რომ გააკეთე `git commit`. თუ კომპიუტერთან საქმეს მორჩი, არ დატოვო ცვლილებები უბრალოდ `add`-პოზიციაში ან მის გარეშე. აუცილებლად დასცხე კომიტი: `git commit -m "update"` და გაუშვი `git push`.


### **რა ხდება, თუ რამე „გამოგრჩა“ და პრობლემა შეიქმნა?**

თუ ერთ კომპიუტერზე ქენი `push`, მერე მეორეზე მიხვდი, რომ წინა მდგომარეობიდან მუშაობდი და `git push` რომ ცადე, შეცდომა ამოგიგდო (ტიპური შეტყობინება: *fetch first* ან *non-fast-forward*):

1. **არ აჰყვე პანიკას და არ წაშალო პროექტი.**
2. გაუშვი ბრძანება : - - -  `git pull --rebase`
3. git შეეცდება, ავტომატურად შეაერთოს ორივე მხარეს გაკეთებული ცვლილებები.
4. თუ ფაილები არ იკვეთება (ანუ სხვადასხვა ადგილას წერდი), ის უპრობლემოდ გააერთიანებს და მერე თავისუფლად გააკეთებ `git push`-ს.
5. თუ **ერთი და იგივე ფაილის ერთი და იგივე ადგილი** შეცვალე ორივე კომპიუტერზე, git გეტყვის, რომ არის კონფლიქტი (Conflict). 
	1. გახსნი იმ ფაილს, აირჩევ რომელი ვერსია გირჩევნია **(სერვერის თუ ადგილობრივი**), შეინახავ, მერე მიუთითებ:
	2. `git add <ფაილის_სახელი>`
	3. `git rebase --continue`
	4. და ბოლოს - - -  `git push`.
