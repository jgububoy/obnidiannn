## 1. **დაყენება და კონფიგურაცია (Setup & Configuration)**
პროექტების თვალთვალამდე, საჭიროა თქვენი იდენტობის კონფიგუeრაცია და რეპოზიტორიების ინიციალიზაცია.

* `git config --global user.name "Your_Name"`: აყენებს თქვენს კომიტებთან დაკავშირებულ სახელს.
* `git config --global user.email "you@example.com"`: აყენებს თქვენს კომიტებთან დაკავშირებულ ელფოსტას.
* `cat C:\\Users\\\boy\\.gitconfig` - - - ფაილი რომელშიც არის. ***global config***.
* 
* `git config --local user.name "<testuser>"` - - - user ***local*** config ( **git init** დირექტორიაში)
* `git config --local user.email "<nj@rs.ge>"` - - -  mail ***local*** config 
* 
* `git init` - - -  ინიციალიზაცია. **ლოკალურ Git რეპოზიტორიას მიმდინარე დირექტორიაში**.
* `git clone <url>`- - - სერვერიდან რეპოზიტორიების ჩამოტვირთვა. ( კლონირება )

## 2. **ლოკალური ცვლილებების მართვა ( commit )**

`< >` - - - ნიშნავს შენი სურვილით ჩანაწერები ( დასახელებები, ID-ები... )

* `git status`- - -  აჩვენებს სამუშაო დირექტორიის მდგომარეობას.
* `git add <file_name>` - - - ფაილი გადაყავს **staged** გარემოში. ამზადებს **დასაკომიტებლად**.
* `git add .`- - -    ყველა  **untracted/modifited**  ფაილი გადაყავს **staged** გარემოში.
* `git commit -m "<your message>"` - - -  **დაკომიტება** "your message" კომენტარით
* `git commit -a -m "<edit file>"` (იგივე **-am** )- - -  მხოლოდ **modifited**  და **stage** ფაილების პირდაპირ დაქომითება (და არა **untracted** ფაილებისა)
* `git commit --amend -m "<new coment>"` - - - ბოლო ქომითის **კომენტარის შეცვლა.**
* `git mv` - - - სახელის შეცვლა ან კატალოგებში ფაილის გადაადგილება. ანუ: 
	* `git mv app.py application.py` - - -  ასე სახელი გადავარქვი
	* `git mv app.py /folder_name/application.py` - - - გადავიტანა და თან სახელი გადავარქვი
* `git diff` - - -  აჩვენებს ცვლილებას  **untrackted/modifited** ფაილებსა და **ბოლო კომიტს** შორის. 
* `git diff --staged` - - - განსხვავება **staged გარემოში** მყოფი  და **ბოლო კომიტს** შორის. 


## 3. **reset** : ( commit -ების წაშლა/გაუქმება ) :

>  **untracked** -ში რაც არის **ვერცერთი ვერ იშლება** reset ბრძანებით --- მხოლოდ **clean**-ით !!!!
>  იმ ლოგიკით რომ ეს გარემო თავისი არსით ნიშნავს, **არ არის აყვანილი აღრიცხვაზე**, ანუ git-ისგან კონტროლს არ ექვემდებარება. თუ მაინც reset-ით გვინდა წაშლა,  **modifited** , **untracked/modifited** ან **staged** გარემოში უნდა გადავიყვანოთ(ანუ **git-ის კონტროლ ქვეშ**) და მერე შეიძლება ამოშლა.

- `   git reset --soft HEAD^`
    - **( commit ==> staged )**
    - **( staged ==> staged )**
    - **( untracked ==> untracked )**
- `git reset --mixed HEAD^` ან `git reset HEAD^`
    - **( commit , stage ==> untracked/modifited )**
    - **( untracked ==> untracked )**
- `git reset --hard HEAD^`   - - - - - - - - - - -  მხოლოდ **ეს შლის** გარკვეულ ფაილებს!!
    - **( commit, stage ==> delate )**
    - **( untracked ==> untracked )**
- `git reset`
    - **( stage ==> untracked )**

ასევე მსგავსი შინაარსით: 
- `git restore <file_name>` - - - **კონკრეტულ ფაილში** განხორციელებულ ცვლილებებს აბრუნებ ბოლო კომიტის მომენტამდე. 
- `git reset <file>` - - -  აუქმებს ფაილის მომზადებას მისი შიგთავსის ცვლილებების შენარჩუნებით.

## 3. **checkout** :  ( დათვალიერება და ფაილის გადმოტანა )

commit-ების **დათვალიერება** და ასევე იქიდან კონკრეტული ფაილების **გადმოტანა** master/main commit-ში - stage გარსში.
**აჩვენებს სხვაობას** კონკრეტულ კომიტსა **და მის პირდაპირ წინაპარს** (ანუ წინა კომიტს) შორის.

1. `git checkout HEAD^^` - - - კონკრეტულ წინა commit-ზე **გადასვლა(ჩახედვა)**
2. `git checkout HEAD~3` - - - იგივე
3. `git checkout <COMMIT_ID>` - - - იგივე
4. `git show <ID>` - - -  ასევე **დაათვალიერებ** კონკრეტულ კომიტს. 
5. `git checkout master` - - -  master commit-ზე შტოზე **დაბრუნება** 
6. `git checkout COMMIT_ID -- file.txt` - - - კოკრეტული ქომითიდან გადმოგვაქვს(ვაკოპირებთ) **file.txt** ფაილები **master** შტოში, რომელიც არის **stage** გარემოში
7. `git checkout <commited_id> -- .` - - - კონკრეტული ქომითიდან **ყველა ფაილების** წამოღება(გადმოკოპირება),
8. `git checkout -- . ` - - - 
	- **სიტუაცია 1**: როცა რომელიმე commit-დან გადმოვიტანეთ რაიმე ფაილი და ახლა  არსებულ **master head**-ში ვართ, ყველა **გადმოტანილი ფაილი** სანამ **stage** გარემოშია ნულდება.
	- **სიტუაცია 2**: როცა არსებულ main commit-ზე ხარ, ანუ მუშაობ ჩვეულებრივ. და შეგეშალა.... ანუ გაანულებს ყველა ცვლილებას რაც მხოლოდ **"modifited"** გარემოშია

## **clean** : ( წაშლა **მხოლოდ untracted** ფაილების )

სინტაქსი:   `git clean [ოფციები]`

- `git clean -n -d`: **შეამოწმებთ**, რა ფაილები და საქაღალდეები წაიშლება **(უსაფრთხო რეჟიმი**).
- `git clean -n` - - - **untracted** ფაილების სიის გამოტანა ( გაიგო დაზუსტებით რომელი ფაილებია )
- `git clean -f` - - - **მხოლოდ** ყველა **untracted** ფაილების წაშლა
- `git clean -f <file_name>`  - - - კონკრეტული **untracted** ფაილების წაშლა
- `-d`: წაშლის არა მხოლოდ untracked ფაილებს, არამედ მთლიან **untracked დირექტორიებსაც.**
- `-x`: წაშლის ისეთ untracked ფაილებსაც, რომლებიც ჩვეულებრივ **იგნორირებულია** (`.gitignore` ფაილის მიერ).
- `git clean -fd`: წაშლის ყველა **untracked** ფაილსა და საქაღალდეს რეჟიმში.
- `git clean -fx`: წაშლის ყველაფერს, მათ შორის `.gitignore`-ში მითითებულ ფაილებსაც (მაგალითად, ქეშს ან აგებულ ფაილებს). 


## 4. **განშტოება და შერწყმა ( Branching & Merging )**
განშტოებები საშუალებას გაძლევთ იმუშაოთ ახალ ფუნქციებზე სტაბილური მთავარი კოდისგან იზოლირებულად.

* `git branch`    - - -  ყველა შტოს **სია** რაც გვაქვს. და რომელზეც დგახარ იქვე მინიშნებულია
* `git branch -r` - - -  აჩვენებს მხოლოდ დისტანციურ ბრენჩებს.
* `git branch -a` - - -  აჩვენებს როგორც ადგილობრივ, ისე დისტანციურ ბრენჩებს ერთად.
* `git branch <branch-name>` - - - - ახალი name შტოს **დამატება**
* `git branch -d <name>` - - -  name სახელის **შტოს წაშლა**. (სხვაზე უნდა იდგე)
* `git checkout <branch-name>` - - - name **შტოზე გადასვლა**. როგორც commit-ების შემთხვევაში გადადიოდი/გადმოდიოდი
* `git switch <nom_branche>` - - -  ესეც **შტოზე(branch) გადასვლა** , თანამედროვე  ვერსია.  შეიქმნა, რომ ჩაენაცვლებინა მრავალფუნქციური `git checkout`, რადგან `switch` სპეციალიზებულია **მხოლოდ შტოების მართვაზე**.
* `git switch -c <branch-name>` - - -  ( **-c** - _create_ ) ერთდროულად **ქმნის და გადადის ახალ შტოზე**
* `git checkout -b <branch-name>`- - - - **თან შექმნა** და **თან გადასვლა** ახალ შტოზე. 
* 
* `git merge <branch-name>`- - - დამატებითი(პირობითად **feature** იყოს) შტოდან ცვლილებების გადმოტანა მთავარ შტოში. მაგრამ უნდა ვიდგეთ მთავარ შტოზე. ანუ ვეუბნებით გადმოიტანოს name შტოდან ინფორმაცია.
* `git push origin --delete feature` - - - შტოს **github(Remote-დან) წაშლა**: ( origin/feature ):

## 5. **გაზიარება და სინქრონიზაცია (Sharing & Syncing)**

გამოიყენეთ ეს ბრძანებები კოდის თანაავტორებთან გასაზიარებლად და ლოკალური რეპოზიტორიების ჰოსტინგ პლატფორმებთან დასასინქრონიზებლად.

- `git remote -v` - - - ამოწმებ ლოკალური მანქანა სადმე თუ არის მიერთებული. ( თუ არაფერი გამოიტანა არსადაა მიერთებული.)
* `git remote add <name> <url>` - - - აკავშირებს თქვენს ლოკალურ რეპოზიტორიას(მანქანას) დისტანციური სერვერის მისამართთან , "**name**" სახელით (ხშირ პრაქტიკაში **origin** სახელით)
* `git remote remove add <name> <url>` - - - ლოკალური მანქანის, რემოუთ სერვერთან **კავშირის გაწყვეტა**

### push - ბრძანება

- `git push` - - - მხოლოდ ამას თუ დაწერ, დაფუშავს **მიმდინარე შტოს** და `-u`-თი მანამდე დამახსოვრებულ შტოს, სერვერზე  შესაბამის შტოებზე.
* `git push origin <branch-name>` - - -  იღებს  ლოკალური მანქანის **"branch-name" შტოდან**,  ***დაქომითებულ*** ფაილებს და ტვირთავს **origin** სეხელზე( მის სახელის უკან **github** მისამართა მიერთებული), ზუსტად იმავე სახელის მქონე **branch-name** შტოზე.   
* `git push --all origin` - - - -  **ყველა შტოს** ერთად **დაფუშავს**. `-u` თი რომც არიყოს დამახსოვრებული. (origin სერვერზე **შესაბამის შტოებზე**.)
	*  
	* `-u` - - - **(ან `--set-upstream`)** ნიშნავს, რომ **git იმახსოვრებს კავშირს** შენს ამჟამინდელ ლოკალურ შტოსა(ამ წამს რომელსაც აგზავნი) და დისტანციური სერვერის(`origin`) შესაბამის შტოს შორის. 
	* `git push -u origin <branch-name>` - - - ერთხელ რომ დაფუშავ.  დაიმახსოვრებს და მომავალში სხვა შტოზე რომ იდგე სახელის მითითების გარეშე(`git push` ) , **ამ შტოსაც დაფუშავს.** 
	* 
* `git pull --rebase` - - -  [obsidian git <- -> git obsidian  ( --rebase )](obsidian%20git%20<-%20->%20git%20obsidian%20%20(%20--rebase%20).md) 
* `git clone <url or ssh>` - - - რეპოზიტორიების კლონირება, **ჩამოქაჩვა** HTTPS ან SSH-ით.
* .
* `git pull`- - -  **ქაჩავს** განახლებებს დისტანციური რეპოზიტორიიდან და ავტომატურად აერთიანებს მათ თქვენს მიმდინარე ლოკალურ განშტოებაში.
* `git fetch`- - - ჩამოტვირთავს ისტორიასა და განახლებებს დისტანციური სერვერიდან თქვენს ლოკალურ ფაილებში ცვლილების ან შერწყმის გარეშე.

**პ.ს.**
***კომიტების გასუფთავება***: 
კომპში რომ გავასუფთავებ **reset**-ით კომიტებს, და მერე მინდა **push** გავაკეთო, 
კომფლიკტშია ისტორიასთან და მეუბნება **pull** გაკეთეო და ასე წრეზე ვარ.   

**რატომ ხდება ეს:** როცა ლოკალურად `git reset --soft`-ით ძველი კომიტები გააუქმე და მერე თავიდან დააკომიტე, 
შენს **ლოკალურ ისტორიას** სრულიად ახალი, სხვანაირი „კუდი“ (`commit history`) მისეცი. 
სერვერზე (`origin`) კი **ძველი კომიტებია დარჩენილი**. 
**git** ხედავს, რომ სერვერი და ლოკალი **ერთმანეთს აცდა**, ამიტომ გთხოვს ჯერ `pull`-ის გაკეთებას.
როცა აკეთებ `pull --rebase`-ს, **git** ცდილობს შენი ახალი კომიტები,  სერვერზე არსებულ ძველ კომიტებს ზემოდან დაადოს, მაგრამ რადგან საწყისი წერტილები აირეა, კონფლიქტში შედის და წრეზე ტრიალებ.

ამის მოსაგვარებლად: 

```bash
git push origin <branch-name> --force-with-lease
```

რა არის `--force-with-lease` - - -  ეს არის უსაფრთხო ძალისმიერი ფიში. 
სერვერს ეუბნება: 
„**გაანადგურე სერვერზე არსებული ძველი აცდენილი ისტორია და ჩაწერე ჩემი ახალი ლოკალური ისტორია**“. 
`--with-lease` ამას აკეთებს უსაფრთხოდ — თუ ამასობაში ვინმე სხვამაც არ ატვირთა რამე იმავე შტოზე.

---

## 6. **შემოწმება და გაუქმება (Inspection & Undo)**

* `git log` - - -  მიმდინარე განშტოებაზე შესრულებული ყველა კომიტის ქრონოლოგიურ სიას.
* `git log -p` - - - დაწვრილებით ინფორმაცია
* `git revert <commit-id>`: ქმნის სრულიად ახალ კომიტს, რომელიც სრულად აბრუნებს კონკრეტული წინა კომიტის ეფექტებს.
